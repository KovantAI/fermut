# fermut vs mutmut — detection parity on pyjwt

- Repo: **pyjwt 2.13.0**, package `jwt/`, same test suite.
- fermut (executed, coverage-filtered): **1634** mutants — 1299 killed / 335 survived.
- mutmut (executed, no_tests excluded): **1575** mutants — 1181 killed / 394 survived.

> The two mutant totals differ because the operator catalogues differ — neither set is a subset of the other. A single "superset" number isn't well-defined; the buckets below are.

## 1. Exact-mutation overlap (same file+line+token change)

- Mutations generated by **both** tools: **264** (of 1634 fermut / 1575 mutmut executed).
  - both killed: 199
  - both survived: 65
  - **mutmut killed, fermut SURVIVED (detection-loss candidates): 0**
  - fermut killed, mutmut survived (fermut advantage): 0

## 2. Line-level detection (catalogue-independent)

- Source lines mutmut detects (kills >=1 mutant): 457
- Source lines fermut detects: 444
- Of mutmut-detected lines that fermut **also mutates** (325), fermut also detects **317** (97%).
- **Lines mutmut detects but fermut misses (has only survivors): 8**
- Lines fermut detects but mutmut misses (fermut advantage): 3

### Lines mutmut detects, fermut does not (inspect)

- `jwt/algorithms.py` — `digest = hashes.Hash(hash_alg(), backend=default_backend())` — fermut survivors only; ops: arg-to-none, keyword-arg-drop
- `jwt/api_jwk.py` — `return PyJWK.from_dict(obj, algorithm)` — fermut survivors only; ops: arg-to-none
- `jwt/api_jws.py` — `headers = self._load(jwt)[2]` — fermut survivors only; ops: number-to-neg
- `jwt/api_jws.py` — `stacklevel=2,` — fermut survivors only; ops: keyword-arg-drop, number-shift, number-to-neg, number-to-zero
- `jwt/api_jwt.py` — `"verify_signature": True,` — fermut survivors only; ops: constant-replace
- `jwt/api_jwt.py` — `now = datetime.now(tz=timezone.utc).timestamp()` — fermut survivors only; ops: arg-to-none, keyword-arg-drop
- `jwt/api_jwt.py` — `stacklevel=2,` — fermut survivors only; ops: keyword-arg-drop, number-shift, number-to-neg, number-to-zero
- `jwt/utils.py` — `int_bytes = bytes_from_int(val, bit_length=bit_length)` — fermut survivors only; ops: arg-to-none, keyword-arg-drop

## Verdict

**Not a clean superset.** On the 264 mutations both tools generate, fermut matches mutmut's verdict on 264 and diverges on 0 where mutmut kills but fermut survives. At line granularity fermut retains 317/325 (97%) of the lines mutmut detects; 8 gaps remain.

Most line-level gaps are `keyword-arg-drop` / warning-`stacklevel` noise (equivalent or near-equivalent). But the `"verify_exp"/"verify_nbf"/"verify_signature": True→False` default flips are security-relevant and **reproducible**:

- The full pyjwt suite KILLS `verify_exp: True→False` (`test_decode_with_expiration` + 2 others fail).
- fermut's full run reports it SURVIVED — while killing the adjacent `verify_iat` flip, so mirror/import resolution is fine.
- Re-running fermut's OWN coverage-selected test set for that line under the same mutation also KILLS it.

So fermut's live run produced a false survivor its own selection should have caught — a candidate test-selection bug, not an equivalence artifact. Worth filing + a deeper dive.
